# Private Vulkan staging policy

`vulkan_query.v` runs the maintained V implementation. It owns the private
root generation, package selection and reports, libc-family checks and aliases,
Lavapipe/Venus installation and ICD paths, compatibility compiler arguments,
certificate assembly, cache validation, and replacement rollback. Native source
and binding files are included in the generation inventory.

The Python entry point preserves argparse and imported APIs. Its synchronous
binding retains imported builders, caller objects and exceptions; standard
library calls handle Debian extraction, JSON spelling and narrow Python views.
The importing context manager remains alive through entered-path conversion and
payload use. Explicit exit preserves active exception context, suppression and
cleanup precedence. The controller is reaped before fallback owner retirement.

Qualification uses the complete frozen original controller and the independent,
unchanged 18-case staging fixture. Paired runs compare every output byte, mode,
link target and compiler/build effect plan. Additional controls cover exported
constant identity and patches, compiler whitespace, arbitrary numeric metadata,
raw link targets, failures, owner entry/exit and process-group interrupts. The
current APFS volume rejects invalid UTF-8 filenames before either controller.
Actual bare mmap32 and early-client library builds compare generated C, x86 ELF
and undefined symbols on ARM and x86 hosts. Offline fake driver builds do not
establish GPU or guest operation. A cold compiler invocation currently emits the
existing cachekey/desktop.v unused-import warning; cold stderr parity is not
claimed. All transport remains counted as Python in the language inventory.
