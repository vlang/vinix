# BCM4378 protocol fixture controller

The Python frontend retains argument parsing, work-directory ownership and the
original print calls. Private host/native phases preserve Python output encoding,
flushing and write errors while V owns the controller policy.
`run-protocol.v` owns immutable oracle recovery, compiler arguments, strict core
and relaxed fixture allocator checks, the exact 27-line golden comparison,
original allocation-site assertions and host/native receipts. The production
core, independent fixture, serial producer and all 26 groups plus 100,000 parser
mutations remain unchanged. Host controller qualification alone does not prove
a fresh kernel build, QEMU run or physical firmware/ring operation.

With the qualified V compiler, the untouched host fixture currently emits
three undeclared `memdup` calls and three pointer-cast errors. The original
Python controller and native controller produce identical generated C and
the same strict diagnostics; controller qualification preserves that failure.

The phase transport restores the caller's original standard descriptors before
starting producers, excludes close-on-exec private owners, and drains large JSON
responses concurrently. The unchanged module and serial producers receive zero
translation credit.

Private environment transport preserves the actual caller's POSIX bytes,
including surrogate-escaped names and values, without runtime-added variables.

The original subprocess text decoder handles `nm` output in a narrow Python
call, preserving locale, UTF-8 mode, universal newlines and decoding errors.
The allocator policy and receipt line splitting remain V. This decoder receives
zero translation credit.
The phase envelope carries the actual parent text codec, including an explicit
`python -X utf8` flag when the environment alone selects another codec.
