Reviewer: /root/lifetime_review (read-only). Checked procns-check.v and the private publisher on 2026-10-22.

The checker requires all published digests and current source digests to match. It checks both architectures; candidate cohorts must have equal before/after counts for every reported size class, zero operation errors, flat big-page counts and no write-after-free counts. Baseline child and concurrent-child cohorts must grow. Four reader workers must each report positive call counts. Both kernels use identical fixture hashes. The unchanged Linux reference must pass using that same fixture hash. The held O_PATH, cwd, parent and inherited cwd marker is mandatory. Six adjacent compatibility fixtures and tracking/production build statuses are required on each architecture. Two subprocess negative controls ensure assertions execute and candidate flat measurements cannot pass as the growing baseline.

The publisher preserves initial failed attempts separately, publishes raw logs and structured receipts, pins source files and retains larger inputs by absolute path and hash. Content-addressed immutable publish destinations refuse replacement by different bytes. Published manifests are evidence records rather than a cryptographic trust boundary: a coordinated rewrite of logs, receipts and their manifest remains outside this checker. Exact baseline commit equality and receipt-level regression serial hashes were suggested to the author as useful provenance tightening; the checked initial publisher already included all regression logs in its digested files map.

Review limits: source review, not an independent rebuild or a proof of every possible malformed log. The checker uses the trusted producer's schema and fixed date directory. Numerical token canonicalization and mandatory membership of every known path in the manifest are not separately enforced. Existing data and source are additionally retained and can be audited directly.
