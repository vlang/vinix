# Desktop and retention qualification

All helper sources and copied modules for this qualification are V. The independent lifetime review is in lifetime-review.md. No repository files were edited by this reviewer.

The first ops preparation used the original cached 6,682,454,528-byte desktop tar. It failed before guest launch: xorriso reported that its 3,263,101-sector ISO exceeded 1,021,986 free sectors. The complete failure remains in perf-ops-producer.log, perf-ops.error, and perf-ops.status (2). Runtime cleanup removed the private VM staging directory. No valid measurement came from this attempt, and automatic build-artifact pruning was disabled.

The retry selects the existing 710,437,376-byte ARM desktop tar at logs/m1-gpu-deploy-20261018/build-support/init-aarch64/initramfs-desktop.tar. Its member listing includes busybox, zsh, true, sleep, curl, DejaVuSans fonts and vinix-desktop. The desktop binary is supplied separately by the overlay. The launcher creates the runtime overlay as raw ustar, avoiding the newer compressed native-fixture ISO builder that the checked kernel cannot unpack.

Modules are copied into frozen-perf. The final driver source lives inside that directory so local module lookup resolves the copied hosttest as well. The earlier desktop-retention-small binary is unused: compiler inspection showed that placing its source at the parent cache directory selected the parent's private hosttest before the explicit module path. No guest was run with that binary. The final executable is desktop-retention-frozen; its compiler log is perf-frozen-compile.log. Each scenario group uses its own process, parent work directory, serial log and QMP socket.

The original/default inputs are pinned in perf-inputs.sha256. The selected smaller image, final driver source/executable, new tracking kernel and desktop executable are pinned in perf-small-inputs.sha256. Final results and post-run verification are recorded separately when complete.

The first smaller-image desktop attempt is an invalid harness run: the cached image lacks od and install. The guest therefore failed to register its user and copy the selected desktop, and readiness timed out after 120 seconds. Preserve perf-small-desktop-producer.log, perf-small-desktop/serial.log, perf-small-desktop.json ([]), and perf-small-desktop.status (1). No kernel qualification is claimed from it.

The desktop retry uses frozen-perf-compat. A V helper copied the initial frozen harness, substituted the literal hexadecimal encoding of the known Perf User name for od, and replaced install with cp plus chmod. These changes affect private test setup only. Sources, both frozen module copies, fixture inputs, driver binaries, compiler and selected image/kernel/desktop are pinned in the perf-*inputs.sha256 manifests.

The retry completed idle, apps and drag on the exact cf642 ARM tracking kernel with the selected cached desktop. All three scenarios reached readiness in one second and measured five seconds. Idle: four processes, 0.38% total CPU, 80.8 MB process memory, 127.0 MB physical memory. Apps: nine processes, 0.92%, 177.8 MB, 245.5 MB. Drag: nine processes, 2.18%, 177.9 MB, 235.7 MB. The numeric and process-tree checks passed; screenshots were not requested, and no visual screenshot comparison is claimed. This is a one-round functional performance qualification using cached desktop and short measurements, not a statistically controlled performance comparison.

The ops/churn/cache guest completed with status 0 and exactly one DONE marker. All 36 distinct operation/directory combinations ran 200 measured iterations after matching warmup and 13-second grace waits; every bytes_per_op value was zero and there were no per-class deltas. All four expected programs ran 300 measured churn iterations after matching warmup: retained_kb=0 and per_run_bytes=0 for each, with no PERF-SLAB delta rows. The cache scenario wrote 32 MiB and retained 20 MiB overall; Cached was 16,384 KiB and Slab 37,168 KiB. Adjacent PERF-MEMINFO agreed on Cached; Slab was 37,200 KiB (32 KiB higher while separate shell probes ran). The cache bounds were declared before the result: used_mb 0..64, cached_kb 0..65,536, nonnegative slab with at most 1 MiB skew between probes.

verify-perf-results.v independently audits raw serial output rather than relying on wrapper status. It verifies expected operations/programs, unique scenarios and process IDs, zero retention/deltas, numeric cache bounds, five-second desktop results, required native app processes, drag drive marker, raw/JSON equality, no PERF-ERROR/panic and one START/DONE pair per valid guest. It also requires two subprocess negative controls to reject (disabled assertions and a desktop log substituted for the ops log). perf-results-audit.log/status record PASS/0.

The original generic SHA helper copied and pinned the frozen modules in memory before guest launch but remained busy hashing the unused 6.68 GB default image. resume-perf-pins.v completed the equivalent sorted manifest later from those frozen copies using the host CommonCrypto SHA-256 primitive, with complete byte-count checks; the unused image hash is retained for the failed preparation, and excluded from post-run used-input checks. Selected image, kernel, desktop and final driver binaries had separate small/compat manifests before their valid guest launches. The frozen used-input manifest additionally includes both copied module/header sets and host dependencies. All used input manifests are checked again after the guest runs.

The first ARM multi-scenario desktop run remains a numeric and process-tree qualification only: its drag scenario followed the apps scenario and no screenshots established that the fixed pointer target reached a titlebar. A separate fresh drag-only guest then used a third frozen harness copy, identical cached image/desktop and exact tracking kernel. It captured a full 2048x1536 QMP screenshot before the input sequence and after the five-second sample. Independent visual inspection by /root/lifetime_review confirmed the System window moved from approximately (580,60) to (82,982); its displayed frame count increased from 5 to 241. This run reported four processes, total CPU 4.56%, process memory 80.8 MB and physical memory 127.2 MB, with status 0 and one START/DONE pair. The before/after PPMs and converted PNGs are retained. The separate V drag auditor checks raw/JSON equality, readiness, drive/shot markers and distinct full screenshots; visual review establishes actual window movement beyond that screen-difference check. These short cached-desktop runs qualify functioning scenarios, without claiming a matched performance improvement or a new desktop build.
