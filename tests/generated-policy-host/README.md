The generated-code and CPU-assembly fixture controllers use `policy_query.v`. V owns
production-function extraction, the Unicode 13 allocation guards, architecture
selection, the privileged PAN replacement, exact independent fixture assembly,
compiler arguments, execution ordering, and temporary-directory retirement.

`vinix_policy_native.py` keeps argparse/import compatibility and transports
original exception objects. Its synchronous callbacks perform only Python
stdlib read/write, TemporaryDirectory, subprocess and print operations. This
preserves the original caller architecture, `env=None`, inherited streams and
unbounded compiler/fixture deadlines. The native owner retires scratch on both
success and error; the transport also cleans outstanding owners if interrupted.
The existing independent C fixture literals retain their original bytes and
assertions. Their move to V string constants is no kernel C migration credit.

Use the original Python entry points or set
`VINIX_GENERATED_POLICY_CONTROLLER` to a prebuilt controller. Compiler selection
for cold invocation follows `build-support/run-v-tool.sh` and `find-v.sh`.
These are host-controller changes: generated-C inputs and existing kernels
must be identified separately from any claim of a fresh kernel build or boot.

The assembly controller preserves the exact privileged-instruction adapters,
15 register-thunk probes, scheduler resume probe, ELF toolchain arguments and
Rosetta execution route. V owns LLVM symbol selection and native fixture
generation; Python int() is a narrow arbitrary-width conversion primitive.
The original assembly and C fixture bodies and all assertions are unchanged.
