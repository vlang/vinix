# Compact Launch options retention preparation

`prepare-options-compact-retainer.v` derives a new compact branch in the
independent source copy prepared by
[prepare-options-width.v](prepare-options-width.v). The original native06
retainer, evidence checker and existing proof branch remain unchanged in their
retained donor. This source preparation does not establish guest acceptance.

For a qualification carrying `compact=true`, the new retainer requires the
eight compact catalog/argument/file/folder/Run frames, the actual compact painted
client, complete compact module source maps and matching staged source copies.
The pre-guest audit record and callback files must match the producer's input
maps. The post-guest record and callback files must match its output maps. Their
paths are fixed to the run's respective `compact-audits-before/` and
`compact-audits-after/` directories. Static replay uses the separate recorded
original-audit API; it makes no new checker-execution claim.

Private baseline clones rebase only their run-owned audit callback paths and
hashes, before reconstructing cloned input/output maps. Original evidence stays
unchanged. All 69 existing refusals remain, with 20 additional compact cases
covering missing frames, wrong geometry/paint, missing or mismatched audit pins,
stripped compact mode, missing source trees, altered staged sources, and fully
resealed audit header/marker/exit/argv/path/reused-phase claims. These new
refusals have been generated; their native execution remains a later gate.
