# Independent Launch options source preparation

The retained native06 fixture is preserved. The maintained
`prepare-options-width.v` creates independent source files for a fresh native
Launch options attempt and consistently selects the qualified explicit wait ABI.
This is source preparation, not native graphical acceptance.

The donor remains
`build/package-hosted-launch-options-guest-worktree`, whose original fixture
and prerequisites are pinned in [native06-plan.md](native06-plan.md). The new
source snapshot copies the selected V, C, header, shell and module inputs,
the required extensionless `compile-v-host`, and the five explicitly named
relative module links. Their canonical target trees are copied independently;
all new link referents must remain within the new source tree. File and
directory modes are preserved. No hard link or clone operation is used.

The source changes are the already qualified `nativeguard`/`recoveryguard`
status storage, one explicit `i32` status slot in the guest's existing bounded
adopted-child poll, and fresh path/environment bindings for the existing host
builder and wrappers. Old inferred-width code is not declared invalid: the
pinned compiler can emit a safe C-int bridge for its builtin wait declaration.
The qualified independent compiler-library overlay is used because other
production imports use an explicit `i32` declaration.

The generated existing builder retains its 40 MiB output cap and 120-second
compiler-child bound. It permits the named controller, retainer, checker and
wrapper builds, retains generated C, uses strict incompatible-pointer errors,
clears inherited environment settings, and binds coherent compiler markers and
private cache/module/temp directories. A bounded complete overlay comparison
against the original qualified manifest runs before and after each phase.
No replacement process supervisor is introduced. The copied supervisor
still requires fresh tool binding before it can be used for a native run.
