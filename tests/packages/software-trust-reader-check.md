# Repository trust details in compact Software windows

Complete admitted enrollment and revocation proposals now prepare canonical and
short pages for the shared report reader. **Read review** is available from the
full proposal and compact windows. It discloses operation, repository ID,
architecture, complete current and previous source URLs/public keys and the
review fingerprint. Enrollment adds the authenticated catalog SHA-256, signed
sequence, remembered replay floor, entry count and expiry in exact Unix seconds.
New identities, same-key source changes and key replacements retain their
specific disclosures; revocation retains its acquisition/launch/rollback denial
and payload/data/history/uninstall effects.

Every prepared byte remains available through three native monospace lines of
at most twelve UTF-8 bytes at 180×220 or larger, and canonical full pages. The
shared fixture reconstructs every canonical page, renders all short fragments
at 180×220 and 320×240, checks native labels and geometry, and exercises page
keys, bounds, full/compact/tiny resize anchors and Back/Escape. The trust reader
keeps proposal identity, literal pending arguments, editable field buffers,
repository selection/scroll and source URL page/seen counters unchanged.
Confirm, Cancel, reload, enroll/revoke, source-URL paging, editing, application
requests and paste cannot pass through the modal. Reading does not satisfy the
existing URL-review confirmation gate. Confirmation remains on the full review.

Cases cover both architectures, two 4,096-byte Unicode source URLs, full-width
unsigned sequence/history values and signed expiry, new/same/rotated keys and
revocation. Live partial and complete-before-exit reads, trust writers and catalog
refresh writers refuse entry. Existing literal service arguments, successful-exit
admission, protected writes, saved-trust/failed-refresh diagnostics and retry
assertions remain in the functional suite. The repository allocation mode adds
reader entry, paging, resizing, ignored mutations, Back and cache retirement to
1,000 enrollment/revocation cycles.

This changes UI disclosure and cache ownership only. It does not enroll a public
publisher, change authentication, protocol, replay floors or the administrator
transport. Host checks do not qualify guest graphical interaction or complete
the broader roadmap 14 release gate.


## Recorded results, 2026-10-15

All fourteen focused compile/run checks passed: the complete Software functional
suite, seven affected allocation modes, ASan/UBSan functional and repository
allocation checks, and native font metrics. Both full desktop architecture
typechecks passed. Repository reader entry, paging, resizing, ignored mutations,
Back, cancellation and cache retirement retain zero tracked bytes over 1,000
enrollment/revocation cycles. The maximum source/counter variants passed in both
functional builds. Sanitizer leak detection was disabled; these results do not
establish whole-service or spawned-worker allocation freedom.

The unchanged maintained distribution staging list needs no new filenames and
was not rerun. Unrelated allocation modes were not repeated. Frozen compiler,
current Software/protocol/UI inputs, staged copies, binaries, generated C and
logs are pinned. Invocations disable cache, fallback and automatic compiler
error reporting. No new guest graphical or broader release acceptance is claimed.
