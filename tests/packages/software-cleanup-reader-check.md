# Complete cleanup reviews in compact Software windows

The admitted obsolete-generation review now prepares owned canonical and short
pages for the existing report reader. **Read review** is available from the full
review and compact windows. Every generation ID, the complete fingerprint,
architecture, retained current/rollback identities, permanent deletion warning,
retention rules and fresh-review requirement remain readable. Empty reviews
explicitly state that no obsolete generations are listed.

At 180×220 or larger the reader uses three native monospace labels with at most
twelve UTF-8 bytes per line. Full-size windows show the canonical page. Arrow and
Page keys, Previous/Next, Back/Escape and full/compact/tiny resize anchors use
the shared report behavior. Returning keeps the underlying cleanup list position.
The reader accepts only disclosure navigation; deletion, reload, cleanup Back,
Stop/Cancel, application requests, editing and pasted commands cannot change the
captured review. Deletion remains on the full review under administrator
authorization. Partial and complete-before-exit reads, approval prompts and
approved writers cannot open the reader or release their existing guards.

The cleanup fixture checks every prepared generation against the decoded list,
fingerprint and retention text, then reconstructs every canonical page from its
short pages. The shared reader assertions render every short page at 180×220 and
320×240, check actual native labels/geometry and resize anchors, and try the
ignored mutations through the app dispatcher. Cases include 30 and 4,096
generations, empty results, both architectures and 20-digit unsigned identities.
Live worker barriers preserve the literal cleanup arguments, fingerprint,
administrator approval and successful-exit admission. The two cleanup allocation
modes add reader entry, redraw, paging, resizing, ignored confirmation/reload,
Back and cache retirement to their 1,000-cycle loops.

The change does not modify package service arguments, cleanup eligibility,
fingerprint generation, protocol, authorization or filesystem deletion. This is
host UI qualification; guest graphical acceptance and broader roadmap 14
publisher/catalog/runtime release qualification remain open.


## Recorded results, 2026-10-15

All 32 focused compile/run checks passed: full Software functional assertions,
all twenty-five allocation modes, ASan/UBSan functional assertions plus the standard
cleanup allocation mode, and native font metrics. The maintained Software-only
distribution driver passed independently with all twenty-five allocation modes
and font metrics. Both full desktop architecture typechecks passed. The two
extended cleanup modes retain zero tracked bytes over 1,000 cycles, including
maximum/empty reviews and prepared-reader cache retirement. Sanitizer leak
detection was disabled; whole-service or spawned-worker allocation freedom and
new guest graphical acceptance are outside these checks.

Compiler invocations use the frozen V compiler with -nocache, fallback and
automatic compiler error reporting disabled. Sources, staged copies, binaries,
logs and helper programs are retained and pinned. Broader roadmap 14 release
qualification remains open.


The optional maximum-size sanitizer allocation loop was deliberately stopped
after more than 21 minutes under heavy concurrent host load. It did not complete
and is not a passing check. The full sanitizer functional suite already covered
the 4,096-generation review, and its standard cleanup allocation mode completed
1,000 cycles with zero tracked bytes. The maximum-size allocation loop passed
without sanitizers both directly and through the maintained driver. No assertion
was relaxed. The original sanitizer logs, binary, generated C and interruption
note are pinned. Its parent only serializes results after every child finishes;
the three observed successful completions were recovered with seconds=-1 to
mark unavailable individual timings. No completed maximum-size sanitizer stress
result is claimed.
