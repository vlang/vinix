# Personal application data in the compact Software reader

An admitted ordinary-account inventory prepares canonical and compact pages for
the shared report reader. **Read inventory** shows the retained-application
count, account scope, package rollback limits, selected ID/location, installed
state and complete diagnostic. The initial overview has no implicit selection;
Next item selects the first application. Item buttons, Up/Down and Tab/Shift-Tab
traverse the current inventory without wrapping. Empty inventories keep their
scope and no-data explanation. Returning to a smaller full list reanchors the
selected row only when the visible row count changes; deliberate paging at the
same size remains unchanged.

Deletion confirmation prepares a separate frozen **Read review** for the exact
ID and account-relative directory, permanent loss, retained granted documents,
live-generation checks and the requirement to confirm on the full screen.
Application navigation is disabled while the deletion ID is pending. The reader
accepts only disclosure navigation: delete/review/confirm/cancel, inventory
reload, application requests, row/list actions and typed/pasted commands cannot
alter the target or start work. Back/Escape retains the inventory or confirmation.
Failed purges rebuild the frozen disclosure for safe inspection before retry.
Root desktops and active inventory/purge workers cannot enter it; existing read
admission and approved-write close guards remain unchanged.

The shared fixture reconstructs canonical text from short pages and checks every
rendered native line and geometry at 180×220 and 320×240, page bounds/keys,
full/compact/tiny anchors and modal isolation. Data fixtures cover initial,
installed, uninstalled, unsafe and empty entries, all 4,096 inventory IDs,
128-byte IDs and complete 512-byte Unicode diagnostics. A real-size list test
returns the last selected application from a large reader to a smaller list and
checks both its visible row and unchanged same-size deliberate paging. Live
partial/complete-before-exit reads and active purges refuse entry. Existing
literal purge arguments, own-account isolation, installed/unsafe denial,
cancellation, live-lease failure, retained completed results and post-purge
reload checks remain in the functional suite.

Both data allocation modes add inventory/confirmation reader entry, item/page
navigation, redraw, resize, ignored deletion/reload, Back, cancellation and owned
cache retirement to 1,000 cycles. This is host UI qualification. No deletion
service/protocol/authorization changes, data-size estimate, recovery promise,
whole-service allocation freedom or new guest graphical acceptance is implied.
Broader roadmap 14 release qualification remains open.


## Recorded results, 2026-10-15

All seventeen focused compile/run checks passed: the full Software functional
suite, nine affected allocation modes, ASan/UBSan functional plus both data
allocation modes, and native font metrics. Both full desktop architecture
typechecks passed. Inventory and frozen-confirmation readers retain zero
tracked bytes across 1,000 decode/item/page/render/resize/ignored-deletion/Back/
cancel/cache-retirement cycles in both data modes. All 4,096 IDs, maximum ID and
Unicode diagnostic, empty inventory, installed/unsafe refusal, initial selection,
read/write barriers, failed-purge review reconstruction and resize selection/
deliberate-paging checks passed in both functional builds. Sanitizer leak
detection was disabled; whole-service/spawned-worker allocation freedom is
outside these checks.

The unchanged maintained staging list needs no new filenames and was not rerun.
Unrelated allocation modes were not repeated. Frozen compiler, current Software/
protocol/UI inputs, staged copies, binaries, generated C and logs are pinned.
Invocations disable cache, fallback and automatic compiler error reporting.
Deletion arguments, own-account guards, protocol, successful-exit admission and
approved-write close guards are unchanged. No guest graphical or broader
roadmap release acceptance is claimed.
