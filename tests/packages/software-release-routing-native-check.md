# Native generic release routing

`software-graphical-check.v --ordinary=true --installed=true --first-run=true
--release-routing=true` qualifies the compositor's fixed
`software.release-review` action with the signed native Counter fixture on both
architectures. The original first-run Review scenario and its historical checker
remain separate; this run does not repeat that historical qualification.

The controller resolves a complete format-2 declaration from the fixture's
authenticated disposable repository copy. Its sole root is `org.vinix.counter`,
with exact version, architecture, repository, publisher, signed index sequence
and canonical metadata digest. The installed disk starts fresh.

The real first-run card is skipped through pointer input. An isolated ordinary
`alex` process then connects to the actual session broker without the compositor
capability. It submits an extra-token action and a malformed action, followed
each time by a FIFO file-dialog barrier. The host requires the rendered dialog,
cancels it through real input, waits for authenticated cancellation completion,
and compares the central desktop pixels exactly before the next action begins.
An acknowledgement alone is insufficient evidence of refusal.

The same client finally submits the literal one-field `software.release-review`
action. The controller waits for Software's actual proposal to render before
targeting its controls. An independent read-only proposal records the exact
signed Counter selection, and the guest verifies no activation or approval
occurred. Installation then requires the separate Confirm and administrator
password steps. Private `skip\n` bytes, mode 0600 and uid 1000 persist across both
cold boots, along with exact account, package and Counter private-data state.
