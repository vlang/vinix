# Explicit 64 GiB coexistence admission

[Runner](run.v) source commit `4fd71712c` adds the explicit
`admit-coexisting-64g ROOT PID` and `start-coexisting-64g ROOT PID` selectors.
The default selectors retain their 32 GiB/quarter-host RAM allowance and
original argument refusals. The diagnostic guest stays at 12 GiB/four CPUs.
Live use of the larger allowance awaits explicit user approval; the user's
**Leave CI running** choice remains in force.

The new policy requires at least 128 GiB physical host RAM and caps aggregate
declared guest RAM at 64 GiB and half host RAM. It retains the single selected
foreign QEMU, executable/resource identity, aggregate CPU, normal pressure and
1 GiB disk reserve checks. Both admission snapshots and launch evidence bind
the chosen policy, limit and divisor. These are admission snapshots, not
continuous host resource monitoring.

Only the new selectors accept `discard=unmap` and `detect-zeroes=unmap` on
writable virtio/qcow2 drives, and exact
`-qmp unix:/absolute/path,server=on,wait=off` syntax. QMP inspection uses metadata
only. Existing endpoints must be single-linked sockets owned by the user;
final symlinks and paths inside the repository or owned stage are refused.
An absent endpoint requires exact `lstat` ENOENT and an existing canonical
parent. Parent path/device/inode/mode/UID are rechecked within each observation
and compared between snapshots; endpoint appearance or disappearance is refused.
Parent aliases such as `/tmp` resolving to `/private/tmp` are supported.
Absence establishes no listener state or explanation for the missing path.
No foreign socket connection, signal or write is performed.
