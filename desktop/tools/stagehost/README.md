# Native desktop source staging

`desktop/tools/stage_app` and `stage_ui2` compile and run native V entrypoints.
The V modules select and normalize sources, remove example entry points and unused
embedded views, render translation and canonical icon data, filter ui2 module
declarations and apply the existing ui2 compatibility substitutions.

`native.v` supplies filesystem operations and matchers for the policies' fixed
patterns. It reuses strict UTF-8 reads, universal newline conversion and the
Unicode 13 word table from `hosttest`. Match offsets are UTF-8 byte positions;
literal POSIX backslashes remain filename characters. The JSON query entrypoint
also runs directly, without callbacks or a Python parent.

The original `open(w)` before example/manifest transformation is preserved with an
explicit stream owner. A close failure supersedes an earlier transformation/write
failure.
Compiler selection uses `build-support/find-v.sh`. A copied entrypoint requires its
complete maintained native source closure, which `sourcefixture.install_stagers`
provides. Generated source comments retain their historical tool names to keep
generated bytes stable.

The independent native fixture checks generated content, links, Unicode pattern
boundaries, rejected entry points and truncation before transformation failure.
See [host-tool qualification](../../../tools/source-tools-native.md) for the
combined package, clipboard, committed presenter and VM controller checks.
