# XNU comparison implementation status

This tracks work against the 49 findings in [the source comparison](macos-xnu-kernel-gap-analysis.md). The comparison remains a dated baseline; this file records changed behavior and remaining work. A partial implementation is not XNU parity.

The environment permits four active agents including the coordinator, so the requested ten specialists ran in successive groups of three; all ten have started and completed initial checkpoints or investigations. Specialists continue with follow-up work. Kernel changes are developed in isolated worktrees under `third_party/xnu-implementation`, reviewed, committed, and integrated on `codex/xnu-integration`. Reviewed checkpoints also reach the shared checkout through scoped commits: `969b3d5b`, `85fb762f` and `646afb93`. Uncommitted work from concurrent sessions is not imported.

## Validation

- `tests/kernel-gaps/run.py`: real static Linux/musl PID 1 programs on ARM64 and x86-64, with mandatory verdicts, failure detection, serial logs and isolated state. Host runner rejection tests and both-architecture guest smoke pass (`71574e19`).
- `tests/block-storage/run.py`: three host fault-model suites pass. These exercise native driver functions; they do not establish real-device power-loss durability.
- `tests/reboot-persistence/run.sh`: ARM64 VirtIO write/sync/reboot/read-back passes.
- `tests/security-audit/test.c`: combined ARM64 and x86-64 guests pass. After the metric-reader correction, retained slab delta is exactly zero after 10,000 producers and after 1,000 collectors on both architectures. The previous seccomp evaluator retained 64 bytes per filtered syscall.

- `fbf31f34` fixes the measured metric-reader, ChaCha scratch, netlink reply-transfer and socket-query leaks. Exact flatness is established for combined IPv6, audit and message-queue paths on both architectures. `646afb93` additionally fixes a measured 128-byte temporary inode retained on each ext2 file-backed page fault, restoring exactly flat combined attribute tests on both architectures. The tracer now accepts the x86 LA57 direct-map stack region and reports usable call chains instead of zero addresses.

- `tests/kernel-allocs/run.sh` with the explicitly pinned V/VEXE currently fails: the available compiler reports many pre-existing allocation kinds beyond the checked-in allowances and exits nonzero for its x86 scratch-tree scan. The allowance file was not broadly refreshed. This is an unresolved validation failure, not a pass.
- Combined release kernel `63b3417e` completes `ops,churn,cache` against the small base initramfs at 2 GiB (one round). The run reports procfs reads at 576 retained bytes per operation, procfs listing at 32,256 bytes per operation, directory listing at 327,168 bytes per operation, and ext2 file/rename operations around 1 KiB per operation. Process churn retains 336–1,328 KiB across 300 invocations depending on the program. These are measured problems to trace; without a matched baseline the run does not attribute them to these changes or establish a leak-free kernel.
- The same combined ARM64 kernel completes desktop `idle,apps,drag` at 12 GiB (one round each, two-second settling and five-second measurement). Desktop CPU use is 0.30%, 0.76% and 5.01% of one CPU respectively; drag records 203 frames. This is a smoke test, not a before/after performance comparison.
- Follow-up native allocation tracing identifies the directory-listing and six-file procfs-read leaks. `tests/kernel-retention/test.c` now passes on both architectures: 200 listings of 128 entries and 200 rounds of procfs reads retain exactly zero objects in all 18/14 slab classes and zero large pages. Small-buffer enumeration and ARM64 `EINVAL` handling are checked too. The broader ext2 and process-churn deltas above remain to investigate.
- Combined ACPI production-callback self-tests and subsequent userspace boot pass on both architectures. The optional-test runner now removes the stale generated-C dependency file when forcing a rebuild.

- `tests/kernel-cpu/check.c`: ARM64/x86 process timers, summed limits, pure-user-loop delivery, SIMD restoration, child accounting and user/system separation pass.
- `tests/mount-policy/test.c`: ARM64/x86 mount, mapping, W^X authorization and repeated-procfs namespace regressions pass.
- `tests/process-inspection/test.c`: ARM64/x86 dumpability, credentials, authorized vector copies, partial/error paths, exec/exit/unmap races and cgroup allocation restrictions pass.

## Completion rules

A row becomes implemented only after its real behavior, error paths, lifetimes and relevant ABI tests pass. Cross-architecture builds, allocation measurements, and guest tests are recorded separately from host models. Hardware-specific features require a supported platform and restoration/persistence testing. Darwin-specific architectures, signing keys, authenticated-root formats and hibernation boot contracts need explicit native designs; placeholder APIs cannot resolve those findings.
