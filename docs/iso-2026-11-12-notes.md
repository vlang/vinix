Vinix iso-2026-11-12 brings desktop, Software, and Linux compatibility improvements, plus new application and platform development work since iso-2026-10-26.

## What’s new since iso-2026-10-26

### Desktop and Software

- **A cleaner desktop:** shortcuts for optional applications appear only when their application payloads are installed. The icon grid closes gaps while preserving saved ordering and drag behavior.
- **Software works better in compact windows:** Launch options, deployment saving, and offline export authoring are accessible in smaller layouts. Repository and policy read failures can be retried without losing drafts, and installed applications can be searched by their retained names.
- **Package development and review:** signed release review covers every selected package root; graphical launch options use signed sessions; Development exports the complete native package source dependency set.

### Kernel and Linux compatibility

- Corrected `poll`, `select`, and `epoll` behavior for ordinary files, `O_PATH` descriptors, event-count limits, invalid output buffers, negative timeouts, and indefinite waits with no descriptors.
- Improved signal compatibility, including alternate-stack inheritance through fork/clone, automatic alternate-stack disarming, Linux signal-action flags, and process-wide reset of one-shot handlers.
- Reduced executable-loader memory retention and fixed ownership of copied execution arguments. Read-only file queries are now admitted under the `rpath` sandbox pledge.

### Application and platform development

The source release also includes the following work. These components have their own build and installation workflows; optional applications are not preinstalled in the desktop ISOs.

- **Native Vox browser integration:** an ARM64 UI2 port renders directly into the Vinix compositor without X11, with native input, tabs, favicons, Vinix font rendering, client-side window decorations, and resident-memory display. This remains a development port; see its [validation and limitations](https://github.com/vlang/vinix/blob/40f802e9575fbb89912518e6b6908ffffc8933fe/tests/vox/RESULTS.md).
- **Wine on ARM64:** fixed translated parent/child JIT code sharing across fork, improved exception-unwind metadata and private runtime/data discovery, and added graphics dependencies and a sandbox-compatible XImage fallback. The signed Wine calculator path gained paint, input, and close validation; this is not a claim of general Windows application compatibility.
- **Android compatibility:** expanded authenticated account services, private persistent account/token storage, authenticator UI handoff, headless service lifecycles, and WebKit-backed WebView transport and cookie handling. Added or corrected Intent/Parcel/Bundle behavior, resource and drawable handling, display metrics, settings, and service queries. Maps/GMS integration remains experimental; complete account sign-in is not claimed.
- **iOS compatibility source:** expanded Foundation/Swift startup behavior, HTTP/HTTPS and URLSession support, operation queues, and per-thread run loops/display links. Added Metal AIR bitcode decoding and bounded scalar integer/floating-point execution. GPU application support remains incomplete. **These source changes are not in the attached iOS runtime**, which is retained from the previous release as detailed below.
- **Experimental PowerPC G4 port:** a native 32-bit big-endian kernel and userspace boot in QEMU with storage, USB input, networking, and desktop application checks. See the [PowerPC port documentation](https://github.com/vlang/vinix/blob/40f802e9575fbb89912518e6b6908ffffc8933fe/docs/powerpc.md). The attached ISOs remain amd64 and ARM64 only.

### Build and release tooling

- Restored desktop cross-builds with current V, including native-size types, host-tool linking, headless UI staging, CPU font measurement, X11 helpers, and bundled validation tools. Fixed package staging workspace cleanup and added checksum/ELF verification for a retained optional runtime.

[Full source comparison with iso-2026-10-26](https://github.com/vlang/vinix/compare/iso-2026-10-26...iso-2026-11-12).

## Downloads and installation

Both desktop ISOs were built from [40f802e9575fbb89912518e6b6908ffffc8933fe](https://github.com/vlang/vinix/commit/40f802e9575fbb89912518e6b6908ffffc8933fe).

| Image | Platform |
|---|---|
| [vinix-amd64.iso](https://github.com/vlang/vinix/releases/download/iso-2026-11-12/vinix-amd64.iso) | x86-64, BIOS or UEFI |
| [vinix-arm64.iso](https://github.com/vlang/vinix/releases/download/iso-2026-11-12/vinix-arm64.iso) | ARM64, UEFI |

Give the VM at least 4 GB of RAM and an empty disk of at least 4 GB (16 GB recommended). The first boot installs Vinix onto the empty disk; subsequent boots keep users, files, and installed applications. Keep the ISO attached. Without a disk, Vinix runs from memory. See the [README](https://github.com/vlang/vinix/blob/40f802e9575fbb89912518e6b6908ffffc8933fe/README.md) for launch commands.

Optional applications and X11 are downloaded when installed. Both architecture-specific X11 bundles and their checksum files are attached.

The separate optional ARM64 iOS runtime is retained from [iso-2026-10-26](https://github.com/vlang/vinix/releases/download/iso-2026-10-26/vinix-ios-runtime-arm64). Its static ARM64 ELF format and published SHA-256 were verified before staging:

`18dcc9cd124c5c647785a84d60a0f084f168bfbba31bb9ce1fb096459f6ec135`

### Tested before release

All six QEMU scenarios passed screenshot, keyboard, and pointer checks:

- amd64 BIOS
- amd64 UEFI installation onto a blank SATA disk
- amd64 UEFI reboot from the installed system
- ARM64 UEFI installation onto a blank VirtIO disk
- ARM64 UEFI reboot from the installed system
- ARM64 UEFI with USB keyboard and tablet

Boot tests used a clean checkout of [26fb20ff139822f30f671284cdc8651248efb8e2](https://github.com/vlang/vinix/commit/26fb20ff139822f30f671284cdc8651248efb8e2), which fixes the host QEMU client's poll declaration. VirtualBox was not tested locally.

ISO SHA-256 checksums are in `SHA256SUMS`; optional assets have individual `.sha256` files.
