# Vinix ISO release, 2026-10-26

Published [iso-2026-10-26](https://github.com/vlang/vinix/releases/tag/iso-2026-10-26)
from `c2762e801be346aeb53b97a1e3d2ecf78d82e798`, pinned on
`release/iso-2026-10-26`. Both ISOs, their checksums, both X11 bundles and
the ARM64 iOS runtime are uploaded. All nine GitHub asset digests match
the local files. The release is public, with draft and prerelease disabled.

The build required native compiler compatibility flags, support for V's
generated `posix_memalign` calls, private imported shadow files, and initial
account databases in compact images. Each fix is committed. AMD64 userspace
was built at `15105ad2d7eaf5ee755d237b1c83550cc78ba2ca`, then its kernel and
account staging were updated through `ff2d8a57158c9246635610f37d77d2d2ae529e65`.
The final compact-account fix only adds missing databases; AMD64 already
contains them and its passing image is unchanged. ARM64 was restaged at the
release revision. The evidence records the complete build sequence.

## Validation

All six final QEMU checks passed, including rendered desktop, keyboard and
pointer checks. Installation checks inspect the installed filesystem before
the same disk is rebooted.

| Architecture | Boot configuration | Desktop reached |
|---|---|---|
| AMD64 | BIOS, i440fx, no HPET, one CPU | 79 s |
| AMD64 | UEFI, q35, blank SATA disk installation | 215 s |
| AMD64 | UEFI, reboot from installed system | 31 s |
| ARM64 | UEFI, virtio input, blank VirtIO disk installation | 76 s |
| ARM64 | UEFI, reboot from installed system | 33 s |
| ARM64 | UEFI, USB keyboard and tablet on xHCI | 23 s |

ARM64 installation and disk reboot used the existing screenshot fallback
when no desktop marker appeared on serial. Rendering and input checks passed.
VirtualBox was unavailable locally. Its [release CI run](https://github.com/vlang/vinix/actions/runs/40242710076)
was queued when this report was written; no VirtualBox pass is claimed.

Both kernel architectures built in production and with allocator self-tests.
AMD64 printed `heap: self-test passed`. ARM64 calls these tests before UART
initialization; retained generated C and subsequent boot progress establish
that the assertions returned successfully. An independent review checked the
new allocator's ownership and ABI. Production kernels were rebuilt cleanly
after self-testing. Account staging regression tests passed.

The unchanged allocation-site audit returned **failure on both the release
kernel and the pre-fix `15105ad2d` baseline** with the same compiler. Both
report 392 ARM64 and 281 AMD64 sites and identical allowlist failures. Only
the source-file count differs because `aligned.v` was added. These existing
findings remain unresolved; the allowlist and checker were not weakened.
