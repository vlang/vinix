# Native source, package and clipboard host tools

The public commands are `desktop/tools/stage_app`, `stage_ui2`, `stage_host_gpu`,
`tools/qemu-package-store`, `tests/packages/test-qemu-package-store`,
`tests/clipboard/test-host` and `tests/clipboard/run-vm`. Their Shell launchers
select V with `build-support/find-v.sh`; their implementations and fixtures are V.
The service supports `--install-server PATH` so launchers finish first-use
compilation before starting their existing bounded readiness timers.

`stagehost` keeps the original source transformations and generated bytes while
using native filesystem operations and fixed-pattern matchers. Its word boundaries
use the qualified Unicode 13 table. Example output is opened before transformation,
so a rejected example still leaves the original truncated destination. Host GPU
staging freezes the presenter and complete native module generator from the
requested Git revision before generating C, its ABI header and the host object.

`packageserver` listens only on loopback and handles requests on owned native
threads. Uploads stream into a private adjacent file, fsync, validate uncompressed
tar entries, atomically replace the previous overlay and fsync its parent. Failed
uploads remove their private file. Source snapshots enumerate live Git files and
configured extras, omit files over 64 MiB, preserve source links and hard links,
and materialize native staging with stable generated metadata. The maintained
staging policy is embedded in the service; rebuilding the service picks up policy
changes. Source and ui2 contents are read again for each request.

Clipboard reads run only on request, retain UTF-8 text bytes, enforce 64 KiB and a
two-second deadline, and retire the helper's private process group. Service workers
check shutdown while waiting on sockets. The service joins them before releasing
its listener and context. SIGINT and SIGTERM yield 130 and 143.

`sourcecommand` owns SDK spawn actions, pipes and private child groups. It drains
stdout and stderr together, bounds capture before appending, and uses `waitid`
with `WNOWAIT` to reserve the child PID until the whole group has been killed and
the leader reaped. The clipboard VM controller uses the original 300-second
deadline, two-second paste delays, QMP event/reply handling, guest environment,
cross-compiler arguments and ten-second shutdown grace. Its console observer and
QMP connection retire before their state is released.

Qualification uses frozen Git source receipts and native independent fixtures;
the original Python files are never executed. Checks cover the six original
package cases, clipboard success/failure cases, Unicode staging boundaries,
live and repeatable snapshots, malformed and short uploads, portable source
closures, committed presenter generation, repeated descriptor baselines, real
Unix-socket QMP exchanges and interrupt/descendant retirement. Native ARM,
Rosetta x86 and ASan/UBSan builds exercise the same suites. The ARM X11 client and
clipboard overlay are also prepared with the existing cross-toolchain.

These host checks do not claim a fresh kernel build or a fresh QEMU clipboard
interaction. The shared CPython package SDK is still used by controllers such as
iOS and remains counted until those consumers have native replacements.
